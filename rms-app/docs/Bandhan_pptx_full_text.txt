- Why the Iterative Model?
- Quick Response - Stakeholders can test each module independently.

- Web-only (no native app)
- Manual payment handling
- No public API
- Basic analytics only
- Despite its strong features, the current Restaurant POS System has some limitations:
- Scalability Constraints:
- The system works well for current transaction volumes but future growth in restaurant size or transaction volume may require additional optimization and scaling efforts
- External System Integration:
- Currently relies on manual processes or file-based integrations for tasks like supplier data updates or accounting software integration
- Limited API-based integrations could streamline these processes
- Mobile Accessibility:
- System is primarily desktop-focused with limited mobile-responsive features
- Staff cannot access full functionality from mobile devices during service
- Real-time Features:
- Basic dashboard functionality without advanced live updates
- Limited real-time notifications for critical restaurant operations
- Advanced Analytics:
- Current reporting focuses on basic sales and inventory data
- Lacks predictive analytics for demand forecasting and customer behavior analysis
